# 产品结构与决策记录

## 核心闭环

知识学习 → 活动报名与实践 → 结构化反馈 → 管理员审核 → 问题/经验整理 → 转为知识草稿 → 内容发布 → 知识更新

## 页面结构

### 志愿者端

1. 首页：学习进度、推荐知识、近期活动、待提交反馈、最新经验
2. 知识库：公开知识与有权限的内部资料、分类、标签、搜索、收藏、阅读记录
3. 问题答疑：常见问题、我的提问、提交问题
4. 活动：活动列表、详情、报名、活动反馈
5. 社群：经验分享、活动复盘、评论
6. 个人中心：资料、收藏、我的反馈、我的提问

### 管理者后台

1. 数据概览
2. 用户管理
3. 知识库管理
4. 问题管理
5. 活动管理
6. 反馈管理
7. 社群内容审核
8. 角色权限管理
9. 系统设置与操作日志

## 关键产品决策

- 注册用户统一获得普通志愿者身份，不设置志愿者等级。
- 志愿者注册仅采集手机号、短信验证码和昵称，手机号作为唯一登录标识。
- 志愿者端和管理端均使用手机号 + 短信验证码登录。
- 管理员入口独立校验管理角色；志愿者入口和管理入口共享账号体系。
- 初始系统管理员只能通过部署手机号、一次性初始化令牌和短信验证完成激活，普通注册页面不能创建管理员。
- 一个用户可拥有多个角色。角色权限和用户单独授权取并集，账号禁用立即失效。
- 知识分为公开、内部、受限三级。受限内容还必须在用户个案 ACL 中授权。
- 未审核反馈只对提交者与反馈审核人员可见；审核通过且选择公开后才能进入社群。
- 反馈审核支持驳回和退回修改。个人感受、主观判断不得自动转换为专业知识。
- 反馈和问题转化为知识时只生成草稿，仍需内容管理员编辑和发布。
- 社群内容默认待审核，审核通过后公开；评论随帖子访问权限控制。
- 后台菜单只做体验层隐藏，所有敏感操作均在 API 层再次校验权限。
- 操作日志记录操作人、动作、对象、IP 与时间，不记录短信验证码和会话令牌。

## 需求冲突与处理

| 需求点 | 处理方式 |
| --- | --- |
| 内部资料、特定案例与“所有志愿者可查看”的表述冲突 | 公开知识对普通志愿者开放；内部资料和受限案例必须额外授权 |
| 活动反馈既要社群可见又要保护隐私 | 默认仅本人和管理员可见，审核通过后由管理员决定是否公开 |
| 独立志愿者端/管理端与同一用户多角色 | 统一身份体系，两个独立入口和布局，登录时校验入口资格 |
| 新志愿者、骨干志愿者等级与“用户不分等级” | 不实现等级，使用角色与权限表达管理职责 |
| 反馈可直接沉淀知识 | 只允许审核人员发起“转为知识草稿”，不允许直接发布 |
